# data/sbom/

Real Syft-generated CycloneDX SBOMs (specVersion 1.7, Syft 1.51.1), scanned
2026-09-17. These replaced the earlier synthetic placeholders generated by
[`scripts/generate_fixture_sboms.py`](../../scripts/generate_fixture_sboms.py)
(kept around for reference/regeneration if needed, but no longer the active
data source).

| file | app_id | source dir |
|---|---|---|
| `hackathon-starter.json` | `hackathon-starter` | `./apps/hackathon-starter` |
| `node-realworld.json` | `node-realworld` | `./apps/node-express-realworld-example-app` (renamed to match our shorter app_id convention) |
| `microblog.json` | `microblog` | `./apps/microblog` |
| `flack.json` | `flack` | `./apps/flack` |

## Known quirks in this real data (handled, not bugs)

- **flack and microblog have no `dependencies` array at all** -- Syft's
  Python cataloger didn't produce component relationships for these scans
  (no lockfile to resolve against). `cyclonedx_parser.py` already handles
  this: every component becomes a direct depth-1 DEPENDS_ON edge, and there
  are no REQUIRES edges for these two apps' packages.
- **hackathon-starter and node-realworld have a non-empty `dependencies`
  array, but the root file node is never linked to anything in it** --
  Syft's npm cataloger records real component-to-component relationships
  but doesn't connect them back to the scanned directory's own root node.
  `cyclonedx_parser.py` falls back the same way (every component becomes
  direct depth-1), while still using the real REQUIRES edges among the
  components themselves.
- **The old "deliberately shared" packages (`lodash@4.17.21`,
  `requests@2.31.0` pinned identically across apps) aren't in this real
  data** -- `lodash` isn't a dependency of either real Node app, and
  `requests` is pinned to different versions in microblog (2.31.0) vs.
  flack (2.9.1), so they don't dedupe into one shared Package node.
  `accepts@1.3.8` (npm) is what the sanity checks and CLI spotlights use
  instead -- a real package naturally shared by hackathon-starter and
  node-realworld's actual dependency trees. There's currently no
  equivalent shared package between the two Python apps; see
  `graph_builder/cli.py`'s `SANITY_CHECKS` comment.
